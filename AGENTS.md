# Fork contribution workflow

This repository is a personal fork. Make changes for this fork first; do not submit anything upstream unless the owner explicitly requests it.

## New features

- Search the fork's existing issues, including closed issues, for related context before starting.
- Create a feature request issue in the fork describing the motivation and intended behavior, unless a suitable issue already exists.
- Make the change on a focused branch and open a pull request against the fork's default branch. Describe the change and testing, and link the issue using a closing keyword when appropriate so merging closes it.
- Keep changes and commits focused so a feature can later be considered independently for upstream contribution.
- Do not merge the pull request or submit it upstream without the owner's approval.

## Other changes

- Before working on a bug fix, improvement, or other change, search the fork's open and closed issues for relevant history, including issues about the original feature.
- Reference related issues in the change or pull request as appropriate; a closed issue may still provide useful context and need not be reopened.
